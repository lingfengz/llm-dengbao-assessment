> 📎 对应 T/ISEAA 006-2024：5.10 供应链管理（供应商审批/协议/漏洞/变更/传输加密/数据出境）

## 第一章 总则

**第一条（目的）** 为防范大模型供应链安全风险（开源模型投毒、第三方服务数据泄露、一体机后门、依赖组件漏洞等），制定本制度。

**第二条（适用范围）** 本制度适用于大模型供应链全环节，包括：基座模型/开源模型引入、第三方大模型 API 服务采购、大模型一体机/算力设备采购、训练数据采购、外包开发与运维服务、SaaS 化大模型工具采购。

## 第二章 供应商准入与评估

**第三条** 大模型相关供应商准入须完成安全评估，评估内容：
1. 资质与信誉（安全资质、合规记录、安全事件历史）；
2. 安全能力（安全认证、应急响应能力、数据保护能力）；
3. 数据合规（是否承诺数据不出境、不用于其他目的）；
4. 供应链透明度（模型来源、训练数据来源说明）。

**第四条** 供应商安全评估由信息安全管理部门组织，评估结论作为采购决策的必要条件。高风险供应商实行"一票否决"。

**第五条** 建立合格供应商名录并动态管理，每年复评一次。

## 第三章 合同与协议要求

**第六条** 大模型相关采购合同须包含以下安全条款：
1. 数据保护条款：数据用途限制、不得将数据用于训练其他模型（未经授权）、数据删除义务；
2. 安全责任条款：安全事件责任划分、赔偿条款；
3. 服务连续性条款：SLA、故障响应时限；
4. 审计条款：我方有权对供应商安全措施进行核查；
5. 合规条款：遵守中国法律法规，数据不出境（涉及重要数据/个人信息时）。

**第七条** 涉及开源模型使用的，留存许可证文本并完成许可证合规审查（商用限制、传染性条款）。

## 第四章 引入与验收

**第八条** 开源模型引入流程：来源登记（名称、版本、哈希、下载来源）→ 许可证审查 → 安全检测（已知漏洞、后门触发测试、敏感能力评估）→ 审批入库。

**第九条** 第三方 API 服务接入流程：安全评估 → 接口测试（鉴权、限流、数据返回范围）→ 密钥管理（不落盘明文、定期轮换）→ 上线审批。

**第十条** 大模型一体机/算力设备验收：硬件完整性检查、固件版本核对、预置模型哈希校验、默认口令修改、管理面安全核查。

**第十一条** 外包开发/运维服务验收：代码安全审计、交付物安全测试、权限交接与账号清理。

## 第五章 供应链风险监测

**第十二条** 建立供应链风险监测机制：
1. 关注开源模型仓库、依赖组件的安全公告；
2. 关注供应商安全事件通报与监管处罚信息；
3. 发生重大供应链事件时启动应急评估（是否停用、替代方案）。

**第十三条** 模型/组件升级时重新进行安全评估，不得跳过。

## 第六章 附则

**第十四条** 本制度由采购部门会同信息安全管理部门负责解释。

**第十五条** 本制度自发布之日起施行。
