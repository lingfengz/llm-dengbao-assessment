## 第一章 总则

**第一条（目的）** 为规范大模型系统部署与运维过程的安全管理，保障训练平台、推理服务、RAG 应用、Agent 应用安全稳定运行，制定本制度。

**第二条（适用范围）** 本制度适用于大模型系统的上线部署、日常运维、变更管理、监控告警、备份恢复与退役下线。

## 第二章 部署安全

**第三条** 大模型系统上线前须完成：
1. 安全配置基线核查（操作系统、中间件、推理框架、数据库）；
2. 漏洞扫描与高危漏洞修复；
3. 网络策略开通审批（最小化原则）；
4. 上线安全验收测试（含大模型专项测试）。

**第四条** 部署架构要求：
1. 训练网络、推理网络、管理网络逻辑隔离；
2. 推理服务仅通过受控 API 网关对外提供；
3. 管理面（模型管理、训练管理）仅限内部网络访问。

**第五条** 大模型一体机部署须额外核查：硬件接口（USB 等）管控、固件版本、预置模型完整性、管理面默认口令修改。

## 第三章 访问与权限管理

**第六条** 大模型系统账号实行实名制与最小权限原则：
1. 管理账号、业务账号、审计账号分离；
2. 特权账号使用双因素认证；
3. API Key 按应用独立申请，定期轮换（建议不超过 90 天），离职/下线应用及时注销。

**第七条** 运维操作通过堡垒机执行，高危操作（数据删除、配置变更、模型替换）须审批并双人操作（如适用）。

## 第四章 监控与审计

**第八条** 建立大模型系统监控体系，覆盖：算力资源（GPU 利用率、温度）、服务可用性、API 调用量、模型响应延迟、内容拦截量、异常调用（高频、越权、注入特征）。

**第九条** 日志管理要求：
1. 系统日志、访问日志、操作审计日志、内容拦截日志统一接入日志平台；
2. 日志留存不少于 6 个月；
3. 日志防篡改（仅审计员可访问）。

**第十条** 建立告警分级与处置机制：高危告警（服务中断、数据泄露迹象、大规模越狱尝试）15 分钟内响应，按《大模型安全事件应急预案》处置。

## 第五章 变更与配置管理

**第十一条** 变更管理要求：变更申请 → 影响评估 → 审批 → 实施 → 验证 → 记录。重大变更（模型替换、架构调整、安全设备策略变更）须经信息安全管理部门会签。

**第十二条** 配置基线管理：核心设备与系统建立配置基线文档，配置变更后更新基线，每季度核查一致性。

## 第六章 备份与恢复

**第十三条** 备份策略：
1. 模型文件：版本发布时全量备份，保留不少于 ____ 个版本；
2. 知识库数据：每日增量、每周全量；
3. 配置与日志：每日备份。

**第十四条** 每半年开展一次恢复演练，验证模型、知识库、配置的恢复能力，演练记录归档。

## 第七章 漏洞与补丁管理

**第十五条** 每月开展漏洞扫描（含推理框架、依赖组件、GPU 驱动），高危漏洞 7 日内完成修复或采取缓解措施。

**第十六条** 关注大模型相关安全公告（框架漏洞、已知越狱手法、供应链事件），及时评估并处置。

## 第八章 退役与下线

**第十七条** 模型/服务退役流程：审批 → 停止服务 → 数据清理（含缓存、日志中的敏感数据）→ 权限回收 → 资产核销。

**第十八条** 退役设备介质按数据销毁要求处理，禁止直接转售或随意丢弃。

## 第九章 附则

**第十九条** 本制度由运维管理部门负责解释，信息安全管理部门监督执行。

**第二十条** 本制度自发布之日起施行。
