# 05 整改要求与整改流程

## 一、整改分级原则

| 风险级别 | 判定场景 | 整改时限建议 | 整改后动作 |
|---|---|---|---|
| 高风险 | 命中 2025版高风险判定指引（含大模型高风险项） | 立即启动，1~2 周内完成或采取临时管控 | 必须复测通过 |
| 中风险 | 可能导致安全事件但不直接致命（如审计不完整、部分配置缺陷） | 1 个月内 | 复测或书面确认 |
| 低风险 | 合规性偏差、建议项（如制度未更新、培训不足） | 3 个月内 / 下轮测评前 | 下次测评验证 |

## 二、整改类型与措施

### 1. 管理类整改（制度/流程/人员）
- 补齐制度文件：直接使用 `assets/制度文件模板/` 的 10 份模板，替换单位信息后发布。
- 建立审批流：模型发布审批、数据出域审批、API 密钥申请审批。
- 培训与考核：大模型安全专项培训（每年≥1 次），保留签到与考核记录。
- 备案补办：未完成算法备案/安全评估的，限期向属地网信部门提交材料。

### 2. 技术类整改（配置/防护）
- 身份与权限：启用双因素、收敛特权账号、API Key 轮换与最小权限。
- 网络隔离：训练/推理/管理网段隔离，边界启用白名单。
- 审计补齐：日志集中接入、留存 ≥6 个月，模型操作全审计。
- 数据防护：语料脱敏、存储加密、DLP 部署。
- 补丁与基线：补丁更新、等保基线核查整改。

### 3. 大模型专项整改（核心）
| 问题 | 整改措施 | 验证方式 |
|---|---|---|
| 越狱/提示注入可突破 | 部署输入输出过滤（关键词+分类模型）、接入 MAF/WAF、升级安全对齐（SFT/RLHF 迭代）、限制系统提示词泄露 | 红队复测拦截率 |
| 内容安全过滤缺失 | 上线内容审核系统（机审+人审）、配置 8 类风险过滤规则、输出标识 | 分场景测试 |
| 无内容标识 | 按 GB 45438-2025 实现显式+隐式标识 | 标识抽测 |
| 训练数据含敏感信息 | 数据重清理+脱敏、建立语料准入清单 | 数据抽测 |
| API 无鉴权/可滥用 | 网关强制鉴权+限流+异常检测 | 接口测试 |
| RAG 数据泄露 | 知识库分级权限、检索结果过滤、注入防护 | 越权测试 |
| 模型投毒风险 | 模型哈希校验、后门检测、供应链评估 | 校验+检测报告 |
| 幻觉率高（高危场景） | 引用溯源、知识库约束、拒答策略、场景化微调 | 幻觉率复测 |
| Agent 工具越权 | 工具权限最小化、工具输出校验、敏感操作二次确认 | Agent 渗透测试 |
| 用户数据违规留存 | 关闭默认用于训练、删除接口上线、留存策略调整 | 删除流程测试 |

## 三、整改闭环流程

1. **整改通知**：测评机构出具问题清单与整改建议（五要素：问题→风险→措施→责任部门→时限）。
2. **整改计划**：被测单位制定整改计划（模板见 assets/模板/大模型整改计划模板.md），明确责任人、资源、排期。
3. **实施整改**：管理类补制度、技术类改配置、专项类上防护。
4. **整改验证（复测）**：测评机构对整改项回归测试；高风险项必须全部验证通过。
5. **报告更新**：复测通过后更新测评结论，出具最终报告。
6. **持续改进**：建立大模型安全月度监测、季度复评机制（对应 LLM-OPS-1）。

## 三.5、整改依据与标准条款引用

整改建议引用条款时，按 T/ISEAA 005-2024 保护要求原文条款（005 与 006 章节号一一对应）：
- 管理/流程类整改 → 引用 005 对应章条（如制度缺失引 6.2 a) 模型安全管理制度、5.11 a) 个人信息管理制度）；
- 技术类整改 → 引用 005 对应章条（如边界防护引 5.3、输入输出过滤引 6.3 a) c)、攻击检测引 8.2）；
- 整改完成后按 006 对应条款复测，验证"x.y.2 测评实施"全部为肯定。

## 四、整改验收要点

- 高风险项：逐项复测，附测试截图/日志证据；临时管控措施须有正式记录。
- 管理类：核查制度发布记录（红头/系统发布）、培训记录、审批单，不能只提供制度文本。
- 专项类：红队测试报告、内容安全测试报告、标识抽测结果须由测评机构或具备能力的第三方出具。
