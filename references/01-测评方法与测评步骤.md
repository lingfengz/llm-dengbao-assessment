# 01 测评方法与测评步骤

> 适用：大模型系统等级保护测评与 T/ISEAA 006-2024 测评（差距测评/等级测评/复测）。测评方法术语与 T/ISEAA 006-2024 对齐（访谈、核查、测试；006 用"核查"不用"检查"），测评过程模型与 GB/T 28448-2019 保持一致，增加大模型专项测试环节。

## 一、测评方法体系

**测评对象（T/ISEAA 005-2024 四层参考架构）**：
- **基础设施层**：计算（GPU 算力）、网络、存储资源；
- **平台层**：模型调优、模型交付、服务运营、数据集、数据工程；
- **模型层**：基础大模型/行业大模型/专属大模型，模型库与模型管理（版本维护/部署/权限控制）；
- **应用层**：Agent、RAG、GPTs、API 等垂类应用与定制开发。

测评实施按"从外到内、从通用到专项"顺序：通用安全（5.x）→ 设计开发（6.x）→ 测试（7.x）→ 部署与运行（8.x）→ 退役（9.x），最后按第 10 章加权判定。

| 方法 | 代号 | 适用场景 | 大模型场景示例 |
|---|---|---|---|
| 访谈 | I | 管理类要求、流程类要求 | 与算法团队访谈训练数据来源；与运维访谈模型更新审批流程 |
| 核查 | C | 制度、配置、日志、记录 | 核查语料来源清单、脱敏记录、模型文件哈希、内容审核日志、备案材料 |
| 测试 | T | 技术类要求、漏洞与配置 | 漏洞扫描、基线核查、API 接口测试、权限测试 |
| 大模型专项测试 | A | 模型与内容安全 | 提示注入、越狱、内容安全、数据泄露、幻觉、鲁棒性、水印检测 |

**方法选择原则**：每类测评项至少选择一种方法；技术类以测试+核查为主、访谈为辅；管理类以访谈+核查为主；大模型专项控制点必须以 A 类测试为主，不能仅凭访谈结论判定。

## 二、五阶段测评流程

### 阶段 1：测评准备

1. 收集资料：定级报告、备案证明、网络拓扑图、大模型系统架构图（训练/推理/管理平面）、模型清单（基座模型、微调模型、版本）、数据资产清单（训练语料、知识库、用户数据）、制度文件清单、厂商设备清单。
2. 调研访谈（首轮）：确认测评对象边界——大模型系统是否与承载系统分离定级；确认模型是自研/开源/第三方 API 调用；确认部署形态（云上/本地/一体机）。
3. 确定测评范围：对象清单（设备、模型、数据、应用、人员、制度）、测评时间窗口、测试许可（红队测试需书面授权，明确不得影响生产与数据）。
4. 编制测评方案：测评依据、指标选取（见 02/03/04）、方法组合、工具清单、进度计划、风险规避措施（测试窗口选择、数据备份、应急回退）。

### 阶段 2：方案编制要点

- 指标选取：通用要求（GB/T 22239-2019 对应等级）+ 大模型扩展要求 + 大模型专项（LLM- 前缀项），三级系统默认全部纳入，二级系统按"技术类全选、管理类全选、专项按实际"选取。
- 工具清单：漏扫、基线核查工具、配置核查工具 + 大模型专项工具（红队测试框架、内容安全测试集、API 测试工具）。
- 风险规避：生产环境测试须避开业务高峰；对抗性测试使用隔离测试账号；越狱测试用例仅在授权范围执行。

### 阶段 3：现场测评（核心步骤）

**第 1 步 访谈**（按对象分组）：
- 安全管理部门：制度体系、定级备案、安全评估开展情况
- 运维部门：网络架构、访问控制、审计、备份、事件处置
- 算法/模型团队：语料来源与过滤、训练流程、模型发布审批、红队测试开展情况
- 业务部门：内容审核、用户投诉处理、标识落实情况

**第 2 步 核查**（按证据类型）：
- 文档核查：制度、审批单、培训记录、应急预案与演练记录、算法备案/安全评估材料
- 配置核查：网络设备 ACL、防火墙策略、身份鉴别策略、API 网关鉴权、模型仓库权限
- 日志核查：审计日志留存（≥6 个月）、训练日志、内容审核日志、管理员操作日志
- 数据核查：语料来源清单、脱敏记录、知识库权限、用户数据删除机制

**第 3 步 技术测试**：
- 漏洞扫描（主机/Web/中间件）
- 基线核查（等保基线、CIS 基线）
- 渗透测试（网络边界、应用层）
- 大模型专项测试（见步骤 4）

**第 4 步 大模型专项测试**（A 类，按 references/07 用例库执行）：
- 提示注入测试（直接/间接注入，RAG 注入）
- 越狱测试（角色扮演、虚构场景、Base64 编码等绕过手段）
- 内容安全测试（涉政、涉恐暴、色情、虚假信息、歧视、违法违规等 8 类，参照 GB/T 45654-2025 安全风险类别）
- 数据泄露测试（诱导模型输出训练数据、PII、知识库内部文档）
- 幻觉与准确率抽测
- API 安全测试（鉴权缺失、越权、限流、敏感信息返回）
- 模型文件完整性测试（哈希校验、版本溯源）
- 标识核查（生成内容是否带显式/隐式标识，GB 45438-2025）

**第 5 步 证据固化**：每项测评填写记录表（见 assets/模板/大模型测评记录表模板.md），截图/日志/配置输出作为取证附件。

### 阶段 4：结果分析

1. 单元判定（T/ISEAA 006-2024）：每个控制点"x.y.2 测评实施均为肯定 → 符合；否则不符合或部分符合"；部分符合项进入风险分析。
2. 分类测评结果：各控制点单元测评结果经算术加权 → 通用安全与各生命周期环节分类测评结果。
3. 整体判定（006 第 10 章）：
   - **符合**：未发现安全问题，所有分类测评结果均为满分。
   - **基本符合**：存在安全问题但不会导致高等级安全风险，且综合得分不低于阈值。
   - **不符合**：存在导致高等级安全风险的问题，或中低风险比例超过阈值。
4. 与等保判定对照：006"符合"≈等保"满足"；"基本符合"≈"基本满足"；"不符合"≈"不满足"（命中高风险即不符合）。
4. 高风险识别：对照 references/06 逐条核对，命中即整体结论不满足，须进入整改。

### 阶段 5：报告编制

报告结构（见 assets/模板/大模型测评报告框架.md）：
1. 概述（委托方、对象、依据、等级、时间）
2. 测评对象与范围（系统架构、模型资产、数据资产、网络拓扑）
3. 测评指标与方法
4. 测评结果汇总（各单元符合率统计表）
5. 单元测评结果（逐项：测评项、要求、方法、结果、证据、发现）
6. 问题清单与风险分析（含高风险判定）
7. 整改建议（五要素：问题→风险→措施→责任部门→时限）
8. 测评结论

## 三、复测（整改后测评）

- 范围：针对上次不符合/基本符合项 + 高风险项进行回归测试。
- 方法：整改措施有效性验证（技术类重新测试，管理类核查执行记录）。
- 结论：复测通过后出具最终测评结论。

## 四、记录与质量控制

- 记录表填写规范：每项记录含测评项编号、测评对象、方法（I/C/T/A）、过程描述、取证附件、判定结果、判定依据说明。
- 双人复核：测评记录由项目负责人复核，抽查比例 ≥ 30%。
- 原始记录保存：测评原始记录（截图、日志、访谈记录）至少保存至测评报告出具后 2 年。
